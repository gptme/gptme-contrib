How does merge sort work?

TL;DR: Merge sort recursively splits an array in half until each piece has one element (trivially sorted), then merges adjacent sorted pieces back together by comparing heads. Time complexity: O(n log n) in all cases. Space: O(n).
Divide and conquer — the big picture

Merge sort is a classic divide-and-conquer algorithm with two phases:

  1. Split: recursively halve the array until subarrays of size 1
  2. Merge: combine sorted subarrays by interleaving their smallest elements

Grey arrows = split phase. Green arrows = merge phase.

The merge step — how two sorted halves become one

Given two already-sorted subarrays, the merge creates a new sorted array by repeatedly taking the smaller front element:

left  = [2, 5, 8]     # sorted
right = [1, 3, 9]     # sorted
out   = []

Compare 2 vs 1 → take 1  → out=[1]
Compare 2 vs 3 → take 2  → out=[1,2]
Compare 5 vs 3 → take 3  → out=[1,2,3]
Compare 5 vs 9 → take 5  → out=[1,2,3,5]
Compare 8 vs 9 → take 8  → out=[1,2,3,5,8]
Drain right    → take 9  → out=[1,2,3,5,8,9]

Each compare does at most one element of work → merge of n elements = O(n).

Python implementation 
def merge_sort(arr):
    if len(arr) <= 1:
        return arr                   # base case: trivially sorted

    mid = len(arr) // 2
    left  = merge_sort(arr[:mid])   # O(n/2 log n/2)
    right = merge_sort(arr[mid:])   # O(n/2 log n/2)
    return merge(left, right)        # O(n)

def merge(left, right):
    out = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    out.extend(left[i:])
    out.extend(right[j:])
    return out

Recurrence: T(n) = 2T(n/2) + O(n) → solves to O(n log n) by the Master Theorem (case 2).

Merge sort is the go-to when stability matters (equal elements keep their original order) and worst-case O(n log n) is required. The O(n) auxiliary space is the usual tradeoff vs quicksort/heapsort.
